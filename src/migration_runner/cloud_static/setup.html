02 / BANDWIDTH PLAN

Size the connection

Bandwidth uses gigabits per second (Gbps). Object sizes use bytes: 8 Gbps equals 1 GB/s before overhead. The examples change only pipe capacity.

Budget = the smaller of your migration ceiling and (pipe capacity × remaining percentage after headroom − other traffic). Actual rates depend on objects, CPU, storage, network, and verification. This preview does not enforce a rate limit.

Network path and endpoint details

These references describe existing or planned infrastructure. Saving this draft does not create a circuit, endpoint, route, or firewall rule.

For a private payload path, validate both directions of routing, non-overlapping address ranges, endpoint access on TCP 443, DNS resolution from workers, and the OCI Object Storage service-gateway route. Authentication, secret retrieval, and monitoring also need reachable service endpoints. A successful sign-in alone does not prove a private data path.

03 / EXECUTION PLAN

Choose worker and copy limits

Recommendations only

Start with two workers and a four-worker ceiling for initial calibration. The preview permits up to 64; availability, shape limits, quotas, and larger fleets require deployment validation. Workers are not automatically provisioned by the current controller.

Use aggregate source application reads per second divided by active workers, measured with the same object mix, CPU allocation, and verification policy. Any configuration change may require recalibration. An OCI-only benchmark does not establish the selected interconnect rate.

Advanced parallelism and run guardrails

Object concurrency is a worker-wide cap shared across batches. Parallel upload buffer estimate = object slots × streams × chunk size. The draft reserves at least half the worker's memory for the OS, clients, and other work. Data limits count scheduled copy bytes; verification and retries add traffic.
